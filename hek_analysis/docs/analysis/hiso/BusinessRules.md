# HISO — Business Rules Catalog

**Summary:** 22 business rules were extracted from source; most concern how clinical form
"concepts" map to stored procedures/columns, how ACC45 (ACC accident claim) data is
built/saved, and configuration-driven behavior toggles — the majority carry High migration
priority because they are undocumented outside the code and config.

## Risks
- Rules BR-05/BR-06/BR-07 (multi-node routing + AWS enrichment + fallback) are complex,
  string-literal-driven (procedure-name allow-lists) business logic with **no unit tests** —
  very easy to silently drop or subtly change during a rewrite.
- Rules embedded purely in `Web.config` (BR-16, BR-17, BR-20, BR-21, BR-22) are invisible to
  anyone reading only the C# source and must be explicitly captured in the future SRS.
- BR-08's "resume only refreshes currentuser fields" behavior is a subtle data-integrity
  rule (prevents overwriting previously captured clinical data) that would cause silent data
  loss/overwrite bugs if dropped.

## Recommendations
- Treat this catalog as the seed for the future unified SRS's "Clinical Forms / ACC45"
  functional requirements section.
- Before any rewrite, get explicit business sign-off on which "dead" branches (static mode,
  `addInvoice`/`launchForm`, the commented-out `mode` classification in `Acc45Builder`) are
  truly obsolete versus incompletely migrated.
