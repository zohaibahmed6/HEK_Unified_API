## Context

## Confirmed findings driving this plan
- **FR-10 risk #1 — path mismatch**: real ERMS/KARO paths are `/api/{OperationName}` (confirmed from `Indici ERMS Web API Specification-v1.1.2.md` and `indici_API_HSS_2.1.3_updated.md`), COL is `/COL/{OperationName}`. This hub currently uses `/erms/...`, `/karo/...`, `/erms/col/...`.
- **New sub-finding**: KARO and ERMS share the identical `/api/{OperationName}` shape but are different systems (historically separate domains). Fix: configurable host-to-system routing (self-managed, zero client-side change), so both can use `/api/...` without colliding.
- **FR-10 risk #2 — HISO transport mismatch**: real HISO is SOAP (`basicHttpBinding`) at `{host}/FormSessionService.svc` (confirmed from `HISO_doc.md`). This hub serves the same logic as JSON at `/hiso/getData`. Fix: convert the existing endpoint to real SOAP at the real address, one door not two.
- **AWS flow**: `AWSDocCore.dll` supplied, confirmed `.NETCoreApp,Version=v8.0` native, exports all 3 methods `IAwsDocumentService` needs — genuine drop-in.
- **Master DB / Second-Node routing**: confirmed global-per-environment (not per-practice) from real source — second-node picked by stored-procedure name (fixed list of 6), master used at one call site. Move from single env-var secrets to an environment-swappable registry table.
- **HISO session expiry**: no such TTL exists in real HISO; our own `ADR-004` 12-hour expiry is invented — remove it.
- **Real write endpoints already exist**: ERMS `POST /erms/SaveDocument`, COL `POST /erms/col/SaveInvoice`. HISO's real writes: `saveContainer` (DMS doc save), `processAction("save"/"addTask")` — no literal "park" method exists in real HISO.
