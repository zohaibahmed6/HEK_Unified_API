Two things worth knowing

The diagram above is drawn as the everything-succeeds path — these are the parts that aren't purely linear.

Routing

Connection is resolved by composite key, not a flat secret

Before this fix, KaroPracticeConnectionResolver built the key Karo:DbCredentials:ConnIndiciDB plus the practice suffix directly — one config entry per practice. Now it asks TenantRegistryService for the row matching PracticeId, PracticeCode and Environment, and only the DB server host needs its own secret. Onboarding a practice onto an existing server needs a registry row, not a config change.

Legacy quirk kept

Two distinct failure messages, on purpose

Legacy returns "Invalid credentials!" when the stored procedure runs clean but produces no real expiry, and a separate "Authentication failed!" when it returns a StatusMessage at all. The handler reproduces both paths exactly rather than collapsing them into one generic error.
