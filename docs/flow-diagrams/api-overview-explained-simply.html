One front door for four different old hospital systems

Some clinics still run on decades-old software. This project is a translator that sits in the middle — it lets modern apps ask one simple, consistent question, then quietly speaks to whichever old system actually holds the answer, in that system's own language.

The journey of one request

Say a clinic's app wants to pull up a patient's record, or save a new note. Here's everything that happens, in plain terms.

1

Someone asks a question

A clinic's software (or this project's own demo screen) sends a request — "give me this patient's demographics" or "save this consult note." It doesn't need to know which old system the data actually lives in.

2

The API checks who's asking

Before doing anything, it checks a login token — like showing an ID badge at the door. No valid badge, no access to real patient data.

3

It looks up which "old building" to call

Every clinic's real records live on a specific, real computer somewhere. The API keeps a kind of phone book (called the Tenant Registry) that says exactly which server holds which clinic's data — so it always calls the right place, not a generic one.

4

It speaks to the old system, in its own language

Each old system — HISO, HSS/KARO, ERMS, or COL — has its own decades-old way of asking for data. The API knows all four "dialects" and asks the real one correctly, fetching the real record or saving the real note.

5

The answer comes back translated

Whatever the old system replies with gets shaped back into the exact same format that system's real users already expect — nothing looks broken or different on their end.

6

The clinic's app gets its answer

The original request finally gets its response — a patient's chart, a saved note, a confirmation — and the person using the clinic's software never had to know any of the steps above happened.

Meet the four old systems

Each one is a real piece of software a real clinic or hospital already relies on — this project doesn't replace them, it just learns to talk to them.

HISO
Handles injury/accident claim forms sent between clinics and ACC (New Zealand's accident compensation system).
HSS / KARO
A GP practice's day-to-day system — patient demographics, consult notes, medications, recalls.
ERMS
Handles referrals and documents moving between a clinic and specialists or hospitals.
COL
Handles billing and claims — the money side of a visit, sent to the practice's claiming provider.

Why go to all this trouble? Because these four old systems were never designed to talk to each other, or to modern apps. Rebuilding them from scratch would be slow and risky for real patients. Instead, this API becomes the one, well-tested translator everyone can rely on.

Every step above is a real, working part of this project — not a simplified fiction. More detailed, technical versions of this same journey (down to the exact code and database calls) live alongside this page in the same folder, for anyone who wants to go deeper.
