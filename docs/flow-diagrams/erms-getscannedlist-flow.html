Two branches worth knowing

The diagram above is drawn as the "everything succeeds" path — these are the forks it can take.

Fail-fast

Token check always runs first

Every ERMS read op — not just this one — goes through the same ErmsReadPipeline: decode/decrypt the patient ID, validate the bearer token against uspInsertAndValidateToken, and only then touch the data procedure. An invalid token short-circuits to an <Error> envelope before any document query runs.

Conditional

AWS-branching document fetch

The exact same real fork implemented for KARO's GetDocuments and HISO's attachment procedures: CheckAwsIsEnabledAsync is checked live, per practice, against that practice's own DB — not a global flag — before deciding which stored procedure variant to call.
