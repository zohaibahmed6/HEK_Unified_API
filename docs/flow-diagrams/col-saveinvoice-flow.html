Two things worth knowing

The diagram above is drawn as the everything-succeeds path.

Architecture

COL genuinely shares ERMS's infrastructure

Confirmed directly in code comments: "COL shares ERMS's auth/connection infrastructure (same in-process legacy controller)." There is no separate ColPracticeConnectionResolver — routing and token validation for every COL call go through the exact same IErmsRoutingResolver/IErmsTokenValidator instances ERMS itself uses.

Observed live, sentinel behaviour

The stored procedure rejects silently, no exception

Confirmed live this session with real (non-duplicate) test values: the procedure returns a value 0 or less via pOutputParam, not an exception — the C# code turns that into "Invalid values passed!". No further detail is available from this layer; the real cause lives inside [OnlineClaim].[uspInsertUpdateService] on the SQL side.
