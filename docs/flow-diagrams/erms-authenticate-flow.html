Two things worth knowing

The diagram above is drawn as the "everything succeeds" path — these are the parts that aren't purely linear.

Routing

Connection is resolved by composite key, not a flat secret

Before this fix, ErmsPracticeConnectionResolver built the key Erms:DbCredentials:ConnIndiciDB{practiceSuffix} directly — one config entry per practice. Now it asks TenantRegistryService for the row matching (PracticeId, PracticeCode, Environment), and only the DB server host needs its own secret. Onboarding a practice onto an existing server needs a registry row, not a config change.

Not this system

This is HEK Core API's own JWT, not what legacy issues

JwtTokenIssuer only appears on the modern (non-compat) auth path. The legacy-compat ErmsAuthenticateQueryHandler above returns the real [HSS].[uspInsertAndValidateToken] token/expiry straight through — same shape ERMS clients have always received.
