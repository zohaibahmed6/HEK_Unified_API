RequiredWhat the spec asks for

Dr. Ahmed Javad's directive: replace three separate integrations (HISO, Karo, ERMS) with one unified REST API Hub that every consumer calls through — with zero change for existing callers (v1.1's sharpened core constraint).

IDRequirement
FR-1/2Extract each system's data set (HISO/Karo/ERMS) and derive one unified/canonical model.
FR-3/4Single REST API; return only what a consumer requests — never "return everything."
FR-5Per-consumer field scoping — a consumer only ever gets its own system's fields.
FR-6Full request auditing: who called, when, exactly which fields.
FR-7/8Extensible gateway — future integrations onboard without redesign.
FR-9Simulation/demo proving parity with each legacy consumer's current API.
FR-10Zero-change guarantee: HISO/Karo/ERMS keep calling exactly as today — same shape, same format.
FR-11Bring all running integrations onto the hub, not just the original three (incl. an unconfirmed "Florence" system).
FR-12Call-flow traceability — show per-request which environment a call originated/routed from.
FR-13Working demo interface (UI), not a bare token/mock exchange.
NFR.NET Core/REST, Docker/containerized, horizontally scalable, top-notch security, full telemetry & logging, systematic error handling, clean minimal code, research-grounded (Azure/AWS gateway patterns).
PR-7Next checkpoint demo: real systems/data (no mocks) + an architecture/call-flow diagram.

Per-system logging overhaul (FR-12/FR-6 follow-on, done 2026-07-29)

  • Per-call human-readable log line (who called, for which patient, what fields came back, which DB server/environment served it — field names only, never values, per NZ HIPC compliance) — centralized in LegacyOperationObserver, covers every legacy-compat endpoint automatically, not just the original pilot RoutingSummaryFormatter.BuildCallLogLine, LegacyOperationObserver.EmitCallLog
  • 12 files total: 4 systems (HISO/KARO/ERMS/COL) × 3 kinds — technical (JSON, 30d), readable (plain-English, 30d), errors-only (90d) — real host folder (logs/{system}/), not a Docker volume, directly browsable docker-compose.yml bind mount, Program.cs per-system sub-loggers
  • Every log line for one request carries a shared CorrelationId (reused existing middleware) so a readable-file entry can be matched to its full technical/error detail
  • Dashboard "Logs" tab — browses these plain-English lines with no terminal/Docker CLI needed, aggregated across all 4 systems frontend/src/LogsPanel.tsx, GET /admin/logs/recent
